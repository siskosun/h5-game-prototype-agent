# Probe to SLICE

Use only after a real human `PASS`.

## Preserve the validated question

Carry the frozen probe card into the SLICE evidence/contract package unchanged. Do not rewrite the probe hypothesis or kill criteria during promotion.

The SLICE `gameplay_contract.md` may add new delivery requirements, quality criteria, systems, and content, but it must link to the frozen probe card rather than replacing its question.

## Choose code treatment explicitly

Record one:

- `KEEP_AND_HARDEN` — retain the probe core and add production safeguards/tests.
- `REWRITE_CORE` — preserve the validated mechanic but replace the authoritative core implementation.
- `REWRITE_ALL` — rebuild the implementation from the frozen behavior contract.

State why. A rewrite does not invalidate the probe's human observation, but it does invalidate implementation/runtime evidence tied to the old build.

## Only now widen production scope

At SLICE conversion:

- choose/confirm DeliveryTarget;
- collect visual references when visual direction matters;
- begin art/audio/presentation work;
- define the full gameplay contract and representative scenarios;
- restore SLICE-scale headless simulation and release evidence.

Keep the user-validated player experience separate from new production assumptions.
